## 本轮 Android 本机路径配置（2026-09-29）

`scripts/build-cocos.ps1` 先解析项目目录，以环境变量 `FLEETING_TOOL_ROOT` 指定工具根目录；未指定时使用项目的上级目录。该目录应包含“需要的软件/CocosCreator/3.8.8”和 `android`，不将某台电脑的盘符写入源配置。

Android 构建会验证当前 SDK、NDK 28.2.13676358、JDK 17 的 `java.exe`、Creator 可执行文件、引擎与调试签名文件存在。准备脚本在当前工程盘符根目录的 `fleeting-build-links/project-{来源路径哈希}` 创建独立任务目录，将 `project`、`creator`、`engine`、`sdk`、`jdk` 五个 junction 分别指向经过核验的真实来源。可用 `FLEETING_ASCII_ALIAS_ROOT` 另指定绝对 ASCII 目录；不会替换中文源码，也不会复制项目或工具。

任务目录的 `owner.json` 记录原始项目、工具根目录、用途及映射。所有已存在入口必须是指向同一来源的 junction，所有者不匹配、普通目录占位或断开的链接直接拒绝；不会覆盖用户目录或静默重定向链接。源码仍保存在原中文目录。

Creator 的 `--project`、可执行文件、临时配置与日志路径保留原真实目录，包括其中的中文。Creator 已在此目录建立资产数据库与脚本 UUID 注册；本轮把它切到 junction 后实际出现 `Missing class` 和空启动组件，不能因退出码成功就接受该包。仅最终 Gradle 工作目录、引擎与 RES/NATIVE、`JAVA_HOME`、`ANDROID_SDK_ROOT`、`ANDROID_HOME`、`ANDROID_NDK_HOME`、签名文件和独立 Gradle 缓存使用 ASCII 别名。

源 `scripts/cocos-android.json` 保持模板，从它在原工程目录生成 `build/cocos-android-current.json`，四项 `sdkPath`、`ndkPath`、`javaHome`、`javaPath` 使用经核验的 ASCII 工具路径。Creator 安装目录的 junction 仅作为原生阶段签名文件的路径入口，不用于启动 Creator。Web 分支不进入 Android 别名准备。

此处理修复了旧源配置和旧生成工程指向 `E:\A Fleeting Life` 的问题。本机 E 盘 SDK/JDK 目录不存在，当前工具位于 D 盘工作目录旁；单独设置环境变量不能替代 Creator 配置的显式路径，也不能覆盖 Gradle `local.properties` 中的 `sdk.dir`。

Creator 生成 Android 工程后，`prepare-android.cjs` 再显式校正以下字段，保证不把旧工程中的 E 盘路径带进 Gradle：

| 文件 | 按当前目录写入的字段 |
| --- | --- |
| `local.properties` | `sdk.dir` |
| `gradle.properties` | `COCOS_ENGINE_PATH`、`RES_PATH`、`NATIVE_DIR`、`RELEASE_STORE_FILE` |
| `cfg.cmake` | `COCOS_X_PATH`，指向独立 ASCII 引擎 junction |
| `res/values/strings.xml` | 中文应用名“浮生” |

Java properties 使用前斜线和标准 Unicode、分隔符转义，路径中的空格保持为合法属性值。本轮编译用属性已全部为 ASCII。脚本先检查工具、引擎、原生源码、生成目录和 keystore，再写入；不存在的 SDK 或签名文件会直接报错。Gradle 的工作目录与启动器也通过整个工程别名访问，不用 `android.overridePathCheck` 跳过 AGP 检查。
